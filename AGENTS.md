# pixbi_lineage — рабочая память

## Что это
Кастомная визуализация lineage данных (путь «источник → витрина → дашборд») для
дашбордов PIX BI. Реализация — один JS-файл на ECharts (`series.type: 'graph'`,
`layout: 'none'`, узлы позиционируются вручную по слоям), без сборщиков и пакетного
менеджера. Живёт локально в `D:\projects\pixbi_lineage`, публикуется в GitHub
(`origin` = https://github.com/Rail-Akhm/pixbi_lineage.git, ветка `main`).
Пользователь — автор дашбордов PIX BI (Rail-Akhm).

## Ключевые факты и грабли
- **Один блок = один `lineage_key`.** v2 ждёт ОДНО вычисляемое поле-категорию
  `lineage_key`, меру `COUNT(1)` (без меры PIX BI вернёт 0 строк) и ПУСТЫЕ серии.
- Формат: `Название::значение::инфо` на сегмент, сегменты через `||`
  (`LAYER_SEP`), внутри сегмента `FIELD_SEP = '::'`. Слой определяется **позицией**
  сегмента, а не названием — одинаковые названия на разных слоях допустимы.
  Число слоёв = число сегментов; добавлять/убирать слой нужно в SQL-формуле, код править
  не надо. Практический потолок — 20 слоёв (длина `COLOR_PALETTE`).
- Найденные в коде константы: `BLOCK_ID` (строка в начале `lineage_v2.js`, тот же ID и
  в `lineage.js` как `const id`, и в `debug.html` — при пересоздании блока править все
  три места), `NODE_W = 160`, `NODE_H = 30`, `V_GAP = 24`, `PAD = 80`,
  `MIN_LAYER_GAP = 80` (в коде помечено `← ПРАВИТЬ ЗДЕСЬ`), `COMFORTABLE_GAP = NODE_W + 80`,
  `EMPTY_LAYER_GAP = 30`.
- **Главная грабля — авто-fit ECharts.** При `layout:'none'` ECharts сам вписывает весь
  граф в контейнер и схлопывает узлы в кучу; декларативные `zoom`/`center` это не лечат.
  Рабочее решение: canvas (`innerEl`) физически равен размеру графа
  (`logicalW × logicalH`), вложен в `scrollEl` с `overflow: hidden`; зум/панорама —
  только через `roam` (нативный скролл перехватывает мышь и ломает `draggable`).
  После рендера `centerScroll()` центрирует вид с повторами (PIX BI грузится асинхронно,
  `clientWidth/Height` могут быть 0). Предыдущие попытки (`CSS transform:scale`,
  фиксированный `NODE_VERTICAL_GAP`, явный `initLayout` zoom/center) в git откачены —
  см. коммиты `5cce3a2`, `3dd8b81`, `24d8551`.
- **`replaceMerge` сбрасывает состояние.** Подсветка/reset должны брать живые значения
  через `currentView()` (zoom/center) и `getCurrentPositions()` (x/y после драга), иначе
  ручной зум и позиции узлов откатываются при hover/click/reset.
- Рёбра строятся внутри строки: сегмент i → ближайший непустой сегмент справа; пустые
  сегменты пропускаются, хвостовой `||` игнорируется. Дедупликация рёбер — `linkSet`
  с ключом `src>>tgt`. ID узла = `${layerIndex}::${value}`.
- Тема берётся адаптивно из `window.themeConfigs`; отслеживание — `MutationObserver` +
  `postMessage` с типом `THEME_CHANGED`. Цвета/тему НЕ хардкодить.
- Нет `package.json`, `requirements.txt`, `pyproject.toml`, docker/Makefile — приложение
  без сборки. ECharts в проде предоставляет хост PIX BI; версия 5.4.3 зафиксирована только
  в `debug.html`.

## Как запускать и проверять
Локальная отладка (из README):
```
npx serve
# открыть http://localhost:3000/debug.html
```
В `debug.html`: выбрать CSV-файл (чекбокс `limit` ограничивает вывод первыми 500 строками),
нажать «Запустить lineage_v2.js» — скрипт подгрузится тегом `<script>`.
Через `file://` не работать (об этом прямо предупреждает `onerror` в `debug.html`).
ID DOM-контейнера в `debug.html` должен совпадать с `BLOCK_ID` в `lineage_v2.js`.

Выкладка в прод — вручную: скопировать содержимое `lineage_v2.js` в кастомную
визуализацию блока PIX BI, предварительно сверив `BLOCK_ID` с ID блока.

Проверка результата — визуально: слои слева направо по числу сегментов `lineage_key`,
узлы `roundRect` натурального размера 160×30, легенда зафиксирована сверху, drag узлов
и подсветка пути не сбрасываются при hover/click/reset.
