# PIXBI Lineage Visualizer

Интерактивная визуализация lineage данных для дашбордов PIX BI.  
Граф направленных связей между слоями данных — от источника до дашборда.

![ECharts](https://img.shields.io/badge/ECharts-graph-blue)
![PIX BI](https://img.shields.io/badge/PIX_BI-custom_visualization-orange)
![License](https://img.shields.io/badge/license-MIT-green)

## Возможности

- **Динамические слои** — число слоёв определяется данными, не требует правки кода
- **Авто-подбор зазора** — слои вписываются в ширину блока, сжимаются до минимального зазора если не хватает места
- **Пустые слои** — не создают пробелов (EMPTY_LAYER_GAP = 30px)
- **Фиксированная легенда** — не скроллится вместе с графом
- **Перетаскивание узлов** — позиция сохраняется после любого hover/click/reset
- **Подсветка пути** — при наведении на узел подсвечиваются все предки и потомки
- **Адаптивная тема** — подхватывает тему PIX BI
- **Zoom / Pan** — колесо мыши + перетаскивание холста

## Быстрый старт

1. Создайте в PIX BI блок с одним вычисляемым полем `lineage_key`
2. Скопируйте ID блока в `BLOCK_ID` в `lineage_v2.js`
3. Загрузите скрипт как кастомную визуализацию

### Формат `lineage_key`

Каждая строка — цепочка пути, сегменты разделены `||`:

```
Название слоя::значение::инфо || Название слоя::значение::инфо || ...
```

Сегменты по позиции образуют слои графа слева направо:

```
Схема::ods_atlas::Домен СИДа || Таблицы::assets::Домен СИДа || Витрины::v_list::Домен СПДа
  слой 0                          слой 1                        слой 2
```

| Часть | Описание |
|-------|----------|
| `Название слоя` | Метка в легенде (слой определяется позицией) |
| `значение` | Имя узла на графе |
| `инфо` | Доп. информация в тултипе (может быть пустой) |

### Минимальная конфигурация блока

| Параметр | Значение |
|----------|----------|
| Категории | Одно поле `lineage_key` |
| Меры | `COUNT(1)` (иначе 0 строк) |
| Серии | пусто |

## Установка

```
lineage_v2.js  — актуальная версия (новые дашборды)
lineage.js     — legacy v1 (для обратной совместимости)
gantt.js       — диаграмма Ганта, режим «Дриллдаун» + gantt_key (основной)
gantt_multi.js — диаграмма Ганта, режим «Все категории» (отдельные колонки)
diag_gantt.js  — диагностика данных Ганта (вставляется вместо gantt.js)
```

## Как это работает

```
lineage_key ──► lineage_v2.js ──► ECharts graph
                                    layout: 'none'
                                    ручное позиционирование
```

### DOM-структура блока

```
el (flex column, overflow: hidden)
├── headerEl (flex-shrink: 0) — HTML-легенда (фиксирована)
└── scrollEl (flex: 1, overflow: hidden)
    └── innerEl (canvas = размер графа)
```

### Ключевые константы

| Константа | Значение | Назначение |
|-----------|----------|------------|
| `MIN_LAYER_GAP` | 80px | Минимальный зазор между слоями |
| `EMPTY_LAYER_GAP` | 30px | Зазор для пустого слоя |
| `COMFORTABLE_GAP` | 240px | Комфортный зазор (NODE_W + 80) |
| `NODE_W` | 160px | Ширина узла |
| `NODE_H` | 30px | Высота узла |
| `PAD` | 80px | Отступ от краёв canvas |

## Технический стек

| Компонент | Технология |
|-----------|------------|
| Граф | ECharts `series.type: 'graph'`, `layout: 'none'` |
| Легенда | HTML (фиксированная шапка) |
| Рендер | Canvas размером графа (обход авто-fit ECharts) |
| Форма узлов | `roundRect` |
| Панорамирование | `roam` + `draggable` |

## Диаграмма Ганта (`gantt.js`)

Отдельная кастомная визуализация: слева колонки **Номер ЗНИ | Исполнитель |
Практика**, справа календарь по дням. Ячейка дня закрашена по `SUM(timeworked_h)`
и подписана часами — цифры появляются только при зуме, когда один день шире
24 px (на обзоре периода остаются только цвета). Сверху — легенда часов,
снизу — слайдер времени. Встроенных фильтров и счётчиков нет: квартал, разворот
групп и статистику задавайте штатными средствами PIX BI.

| Параметр блока | Значение |
|----------------|----------|
| Категории | одно вычисляемое поле `gantt_key` (см. ниже) |
| Меры | `SUM(timeworked_h)` |
| Серии | пусто |

`getItemData` этой версии PIX BI возвращает **только первую категорию**, поэтому
пять полей склеиваются в одно вычисляемое поле через `|~|`:

```sql
concat(
  coalesce(toString(dt), ''), '|~|',
  coalesce(zni_number, ''),   '|~|',
  coalesce(full_name, ''),    '|~|',
  coalesce(practice, ''),     '|~|',
  coalesce(qrt, ''),          '|~|',
  'zni_name=', coalesce(epic_summary, '')
)
```

Шестая часть `zni_name=…` — описание ЗНИ: показывается во всплывающей подсказке
при наведении на номер ЗНИ в левой панели. Метка `метка=значение` снимает
неоднозначность для свободного текста; её можно ставить перед любой частью
(`dt=`, `zni=`, `person=`, `practice=`, `qrt=`, `zni_name=`), порядок частей
не важен. Без описания ключ остаётся рабочим.

Порядок частей фиксирован: `dt | zni_number | full_name | practice | qrt`
(+ необязательная `zni_name=…`). Дата приводится к строке (`toString`), иначе
`concat` может не сработать. Если блок вернёт только одну категорию, визуал сам
покажет эту формулу на экране диагностики.

Ключ универсален: частей может быть от 2 до N (например, только категория
и дата) — `gantt.js` распознаёт их по форме значений, а части `метка=значение`
читает по метке в любом порядке.

Локальная отладка — `debug_gantt.html` (мок `getItemData` + CSV,
`npx serve` → `http://localhost:3000/debug_gantt.html`).
`?format=csvkey` собирает данные из реального `gantt_key` в CSV,
`?format=keydesc` добавляет описание ЗНИ (`zni_name=…`),
`?format=allcats` имитирует режим данных «Все категории» (`values + columns`,
все поля отдельными колонками, мера названа `SUM('v_serv_jira_zni_gant'[timeworked_h])`),
`?ztip=<индекс>` показывает подсказку описания без hover,
`?diag=1` запускает `diag_gantt.js`.

### Несколько категорий

Если в блоке нужны отдельные поля (без склейки в `gantt_key`), выберите
в настройках блока режим данных **«Все категории»**: тогда `getItemData`
возвращает `{ values, columns }`, где каждая категория — отдельная колонка.
В режиме «Дриллдаун» платформа отдаёт только текущую (первую) категорию.

Для этого режима есть отдельный файл **`gantt_multi.js`** — тот же визуал,
заточенный под «Все категории»:

| Параметр блока | `gantt.js` | `gantt_multi.js` |
|----------------|------------|------------------|
| Режим данных | «Дриллдаун» | «Все категории» |
| Категории | одно поле `gantt_key` | `dt`, `zni_number`, `full_name`, `practice`, `qrt` (+ `epic_summary`) |
| Меры | `SUM(timeworked_h)` | `SUM(timeworked_h)` |
| Серии | пусто | пусто |

Основной вариант `gantt.js` не меняется. `gantt_multi.js` отличается подписью
версии `v1.0-multi` в шапке, `BLOCK_ID` можно переопределить через
`window.__GANTT_MULTI_BLOCK_ID__`, а часы находятся и в колонке с именем-мерой
(`SUM('v_serv_jira_zni_gant'[timeworked_h])`). Остальное — строки ЗНИ,
свёртка групп, крутилка, зум, описание ЗНИ, цвета практик — идентично.

Проверка на стенде: `debug_gantt.html?multi=1&format=allcats`.

`diag_gantt.js` — короткая диагностика именно данных Ганта: вставляется в блок
вместо `gantt.js` и печатает на экране, сколько строк пришло, как разбирается
`gantt_key`, что попадёт на диаграмму (ЗНИ, исполнители, период, часы) и итоговый
вердикт. Полезен, если график пустой или строки не распознаны.

Если платформа не отдаёт отдельные категории, в блок можно временно вставить
`diag_categories.js` — он печатает на экране полную диагностику ответа
`getItemData`: какая структура пришла, где искать остальные поля и какой способ
чтения работает. Первой строкой — короткий итог.
